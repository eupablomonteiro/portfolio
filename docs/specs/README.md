# Specs

Uma pasta por feature: `docs/specs/<slug>/`.

Arquivos esperados:

- `spec.md` — problema, cenários, critérios de aceite, não-objetivos e edge cases.
- `plan.md` — arquitetura, contratos, dados, riscos e validação.
- `tasks.md` — tarefas pequenas e testáveis, em ordem de dependência.

Use `_template.md` como ponto de partida e os comandos `/spec` e `/plan-feature`.

Specs são contratos vivos. Se o comportamento mudar durante a implementação, atualize a spec e registre o motivo antes de continuar.
